# Meat Protocol とは？

Meat Protocol は、人間がシステム間の情報または操作の経路の一部を担うワークフローの非公式な呼び名です。「meat」は relay を行う人間の身体を指します。名称は遊び心のあるものですが、観察の対象はインタラクションデザインです。

人間の関与自体を失敗とは見なしません。どの役割を人が担い、その一部を機械的作業として分離できるかを問います。

## 人間の役割

| 役割 | 問い | 例 |
| --- | --- | --- |
| Selection | 何が対象か？ | 「この3つのファイルを比較して」 |
| Routing | どこへ送るか？ | 関連するプロジェクトを選ぶ |
| Transform | どう変えるか？ | ペイロードを整形または墨消しする |
| Judgment | 何を意味するか？ | エラーが重要かを評価する |
| Approval | 実行してよいか？ | 共有または実行を承認する |
| Transport | どう運ぶか？ | パスをチャット欄にコピーする |

## 候補を判定するテスト

Meat Protocol の候補は、人がシステム間の情報または操作の経路の一部を担い、その役割の少なくとも一部を機械的作業として分離できそうなワークフローです。

問いかけます。**その操作をするたびに、本当に新しい判断をしていますか？** 繰り返しにより、以前の判断がルール、コンテキスト、メタデータになり、Mechanical Human Work だけが残る場合があります。

## 分類と自動化

分類と自動化は別問題です。各役割について、技術的に自動化できるか、自動化する価値があるか、安全か、意図的に人間へ残すかを検討します。Transport は典型的な候補ですが、Routing、Transform、Judgment、Approval も条件次第で自動化できます。
