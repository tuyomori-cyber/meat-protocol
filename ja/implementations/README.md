# Meat-to-Auto 参照実装

実装は、人力の橋渡しが実際にどう減ったかを示します。人の判断を自動化する必要はありません。意図的な選択を保持し、分離可能な機械的受け渡しを自動化することが優れた実装です。

## Primitive IO

Primitive IO はこのアプローチの例です。ChatGPT 内に Dropbox のファイルツリーを表示し、人が Markdown またはテキストファイルを選ぶと、その参照をチャット入力へ渡します。公式 Dropbox 統合がファイルを読み取れます。

```text
改善前
Dropbox → 人が検索 → パスをコピー → チャットへ戻る → 貼り付け

改善後
チャット内の Dropbox ツリー → 人が選択 → Primitive IO が参照を運搬 → チャット
```

### 人間の役割

- **Selection:** ソースとファイルを選ぶ。
- **Transport:** 参照をチャットへ渡す。

### Mechanical Human Work と自動化

パスのコピーとアプリケーション切替は機械的作業です。Primitive IO は人の選択を保持したまま、この受け渡しを自動化します。

```text
人間         = 選択者
Primitive IO = 運搬者
```

以前のワークフローには、ChatGPT へ Markdown 化を依頼し、全文選択、コピー、ローカルエディタを開く、ファイル作成、貼り付け、保存も含まれていました。保存先プロジェクトが安定したルールになれば、その多くも Mechanical Human Work になります。一方、正しいプロジェクトを選ぶことは Routing 判断を必要とする場合があります。

将来の API、プラグイン、MCP サーバー、共有ストレージ統合は同じ受け渡しを別の形で解決できます。Meat-to-Auto は、自動化と意図的に残した人間の役割をともに記録します。
